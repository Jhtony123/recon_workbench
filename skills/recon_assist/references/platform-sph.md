# 视频号（sph）账单整理 · 平台技能文档

> 适配器：`core/platforms/sph.py`（承接 bill_arr.wechat_vd_arr ≈138 行）。
> 总体方法论见 bill-methodology.md。注意与淘系微信支付（taobao 的 wechat 源）是
> **两个不同平台**：视频号是微信小店资金流水 xlsx，淘系微信是淘宝交易结算 xlsx。

## 1. 数据源

- 单源 xlsx 资金流水（文件名 `资金流水_wx{appid}_{导出时间}_1.xlsx`；同目录 zip 忽略）。
- 必需列：流水单号/记账时间/动帐类型/收支类型/收支金额/关联订单号/详情。
  ⚠️「动**帐**」是上游原字（不是「账」）；「记账时间」值带反引号 \` 前缀需剥。
- 收款=收支类型'收入'的收支金额，退款='支出'的收支金额（金额本身为正）。
- 账期过滤用「记账时间」取日期。

## 2. 分类：动帐类型字典（单层，无备注链）

TYPE_DICT（16 条）：订单结算/订单支付/订单退款/订单交易｜先用后付/回补极速退款垫资/
极速退款垫资/平台现金券优惠/平台优惠补贴 → **货款**；运费险/技术服务费/达人佣金/
提现/充值/平台赔付/服务充值账户充值(→服务充值) 各自成类。未命中 → 「未匹配」。

- 字典可被 biz_code 规则表整表覆盖（首次热修先全量导入 TYPE_DICT，方法论 §3）。
- ⚠️「订单交易｜先用后付」里的竖线是**全角｜**，上游改半角会失配落未匹配——
  这是最可能的漂移点，未匹配清单里见到「订单交易|先用后付」即此因。
- 无硬对平门；自检靠未匹配占比 + 透视合计 vs 原始收支合计（AI 主动比）。

## 3. 交付物

`视频号_视频号_{店名}_{编码}_{账期}_账单整理.xlsx`：氚云导入模板 + 透视 +
视频号账单整理（8 列：流水单号/资金日期/动帐类型/实际业务类型/收款/退款/关联订单号/详情）。

店铺编码注意：C3 店是 **SHP004**（不是 SPH004，店铺映射原样），传错编码会回落
shop_code 当店铺名。

## 4. 漂移应对速查

| 症状 | 先查 | 修法 |
|---|---|---|
| 「缺少字段」 | 动帐/记账用字、列名变化 | 改 REQUIRED_COLUMNS（代码级+回归） |
| 未匹配出现「订单交易\|先用后付」 | 全角竖线变半角 | biz_code 补半角键，或字典同时收两种写法 |
| 未匹配新类型 | 微信小店新增动帐类型 | biz_code 热修（先全量导入） |
| 金额方向反 | 收支类型文案变（收入/支出） | 确认口径后修 where 条件 |
| 日期全空 | 记账时间格式变 / 反引号外的新保护符 | 扩展剥离与解析 |

基准回归锚点：SPH001（10880 行）/ SPH003（2691）/ SHP004（59）/ SPH005（5），
2026-08 四店全部逐 sheet 对平。
