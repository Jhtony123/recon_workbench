# 京东（jd）账单整理 · 平台技能文档

> 适配器：`core/platforms/jd.py`（承接 bill_arr.jd_arr + jd_Ecard + jd_wallet_arr +
> jd_wallet_arr_final + look_sku.jdwallet_time / bill_arrange_jd）。
> 总体方法论见 bill-methodology.md，本文只写京东特有口径与漂移应对。

## 1. 数据源：三源平台（与其它平台最大差异）

| 源 | 目录约定 | 读取参数 | 必需列 |
|---|---|---|---|
| **钱包流水（主源）** | `<root>/京东钱包/*.csv` | `skiprows=6, encoding=gbk` | 日期 / 商户订单号 / 收入金额(元) / 支出金额(元)；备注列名「资金动账备注」，缺失时用「交易备注」兜底 |
| **结算单** | `<root>/*结算单*/**/*.csv`（可含年份子目录） | `encoding=gb18030` | 账单日期 / 订单编号 / 费用项 / 金额 |
| **E卡** | `<root>/E卡/*.csv` | `encoding=gb18030` | 订单编号 / 金额 / 完成时间 |

- 用户只需给**账单根目录**，适配器按子目录名（钱包 / 结算单 / e卡，大小写不敏感）自动发现；
  也可 `extra_files={"wallet":[...], "settle":[...], "ecard":[...]}` 显式指定。
- 没有「结算单」子目录时兜底取根目录 csv。**E卡缺列的文件会被静默跳过**（不报错）——
  E卡簿为空时先怀疑列名漂移。
- csv 内 ID/日期列带 `="..."` Excel 防科学计数法包裹，统一剥离；金额 `--` → 0。
- 结算单文件按文件名 `_YYYYMM_` 挑账期内的月份（单月可达 5-12MB，避免读全量）；
  文件名不含月份的保守纳入。**上游改文件名格式会导致选错/漏选文件**。

## 2. 账期口径（京东独有，最易错）

**结算单账期不是用户填的 s_date/e_date**，而是：
1. 钱包流水先按用户账期过滤（「日期」列）；
2. 从钱包「资金动账备注」正则提取 `YYYY年M月D日` → 「备注资金日期」；
3. 取其 **min~max** 作为结算单账期（look_sku.jdwallet_time 口径）。

2026-08 JD001 实测推断账期 = **2026-07-31 ~ 2026-08-30**（跨月边界正常，不是 bug）。
该账期同时是 SKU 匹配窗口（match_window）。

**用户日期参数口径（2026-11-16 用户确认）**：京东整理对象是京东钱包（批次资金流水，
无订单号——订单号在结算单里），所以**钱包+结算单必须同时提供**；E卡是额外补充
（消费者独立结算通道，有钱包 E卡货款 时必须纳入交叉校验，原脚本此处金额核对不平即终止）。
钱包/结算单有**一天到账延迟**：8 月账期的日期窗口应为 **7月31日~8月31日**（上月末~月末）。
pipeline 已实现：只给 period 未给 s/e 时自动推「上月末~月末」；显式给 s/e 则尊重用户。
AI 引导用户跑京东时按此口径给日期，不要默认 8月1日起。
实证：固定 8/1~8/31 → 商家结算款差 67084 分 → 替换判定翻转 → 19 类只对平 10 类。
**账期口径是京东能否对平的决定性因素。**

漂移点：上游改备注话术里的日期格式（如 `2026-08-01` 替代 `2026年8月1日`）→
正则 `_DATE_IN_NOTE` 提不到 → 回落用户账期 → 对平门可能翻转。
诊断：看 job result 的 `match_window` / diag.inferred_period 是否还是「上月末~本月末」形态。

## 3. 钱包分类链（四级 + 细分，顺序敏感）

```
c1: 备注含「货款」或「退货」→ 货款，否则 其它
c2: (c1==其它) AND 备注含提现关键字 → 提现
c3: c2==其它 → 交易费用
c4: (c3==交易费用) AND 商户订单号长度≠32 → 账扣费用
最后: 账扣费用 → bustype_split 按备注细分（顺序敏感！）
```

**提现关键字**：`提现` + 店铺氚云名称原文 + 去下划线变体（如 `京东_秋水伊人旗舰店` /
`京东秋水伊人旗舰店`）；规则 `biz_code/jd_withdraw_keyword` 可追加。
⚠️ 已知坑（2026-11-16 修复）：氚云名称已含「京东_」前缀，不能再盲目加前缀，
否则 `京东_京东_…` 永不命中 → 提现整类丢失（透视 18 类 vs 基准 19 类）。
⚠️ 历史坑：c2 的关键字条件必须先 OR 再与「其它」AND；写反会提现虚增 1270 万分。

**bustype_split 顺序**（改序=对平门翻转，动它必须回归）：
京东开放物流费用 → 京东联盟扣款 → 直赔退款代扣(→小额打款) →
处理消费者售后退款问题[无价保](→货款退款) → 处理消费者售后退款问题[含价保](→价保退款) →
理赔单号(→理赔) → 京东联盟 → 先行赔付(→订单赔付) → 结算单号(→E卡货款) →
FCS-备款(→E卡货款) → 日商家结算款(→商家结算款) → 兜底账扣费用。

## 4. 两道金额门 + 商家结算款替换

1. **E卡交叉校验**（硬门）：钱包「E卡货款」现金流合计 == E卡表现金流合计（分位）。
   不平 → BillParseError（原脚本 exit()）。E卡**不进账单层**，只做校验与匹配层。
   不平先查：E卡文件与钱包是否同账期、E卡列名是否漂移被跳过。
2. **商家结算款替换**（软门）：钱包「商家结算款」现金流 == 结算单现金流合计（分位）
   → 相等：透视中商家结算款整类替换为结算单透视（账单类型=京东结算单，19 类形态）；
   → 不等：只导出钱包透视（不报错！）。
   **诊断入口**：job result / adapter.last_diag 的 `replaced_merchant_settle`、
   `nc_wallet_fen`、`nc_js_fen`。没替换时先看差额，再查账期推断与结算单文件完整性。

## 5. 结算单分类

费用项含「货款 / 预售首付款 / 价保扣款」→ 货款；
「售后卖家赔付」「返还运费」且金额<0 → 货款；其余费用项**原文即业务类别**。
⚠️ 这意味着**京东结算单新增费用项会自动成为新类别**出现在透视里（不像编码字典平台
落「未匹配」）——每月 diff 透视类别，新费用项要引导人类确认氚云侧是否需要新科目。
账单日期格式 `%Y%m%d`（如 20260801），解析失败回落通用解析；上游改格式需关注。

## 6. 匹配层 ≠ 账单层（刻意不同，不要"统一"）

匹配层（bill_goods 底稿）= 结算单「货款」 + 钱包「货款退款」（改判货款，订单号从
备注正则 `(对应)?订单号(\d+)` 提取） + E卡「货款」。
**钱包自身的「货款」类不进匹配层**——原脚本既有口径。

## 7. 交付物

- `京东_…_京东钱包整理.xlsx`：氚云导入模板 + 京东钱包透视（替换后）+ 京东钱包明细 9 列
  （账户名称/资金发生日期/商户订单号/资金动账备注/备注资金日期/业务类别/收款/退款/现金流）
- `京东_…_京东账单整理.xlsx`：京东结算单透视 + 结算单明细 8 列
- `底稿/京东E卡_….xlsx`：E卡校验底稿（非交付件）

## 8. 漂移应对速查

| 症状 | 先查 | 修法 |
|---|---|---|
| 「钱包流水缺少字段」 | skiprows=6 是否还对（上游加/减表头行） | read_option 热修 skiprows；列名变了改 WALLET_COLUMNS |
| 「缺少资金动账备注与交易备注」 | 备注列改名 | 改 _clean_wallet 兜底列名（代码级+回归） |
| 提现类消失 | 店铺氚云名称变更 / 备注话术变 | biz_code/jd_withdraw_keyword 追加新关键字 |
| 透视只有钱包类（没替换） | diag.nc_wallet_fen vs nc_js_fen 差额、inferred_period | §4 软门诊断；结算单文件名月份格式 |
| E卡校验不平 | E卡文件账期 / 列名漂移被跳过 | 补文件或修 ECARD_COLUMNS |
| 透视冒出新类别 | 结算单新费用项（§5） | 引导人类定氚云科目，无需改码 |
| 货款退款行订单号为空 | 备注「订单号xxx」话术变 | 修 _ORDER_IN_NOTE 正则（代码级+回归） |

基准回归锚点：JD001 2026-08，钱包透视 19 类逐分对平（含替换），
基准文件 `京东_京东_秋水伊人旗舰店_JD001_2026年08月-2026年08月_京东钱包整理.xlsx`。
