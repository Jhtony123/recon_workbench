# 好衣库（hyk）账单整理 · 平台技能文档

> 适配器：`core/platforms/hyk.py`（承接 bill_arr.hyk_arr ≈238 行）。
> 总体方法论见 bill-methodology.md。

## 1. 数据源

- 单源 csv 货款月明细（文件名 `货款月明细{YYYYMM}-{YYYYMM}（结算月份＆创建型维度）.csv`；
  同目录 zip 忽略）。读取：**gb18030，全列 dtype=str**。
- ⚠️ **所有列名与单元格值都带反引号 \` 前缀**（`订单号、\`2026-08-31 00:00:00）。
  清洗：列名按 _RENAME 映射 + lstrip('\`') 兜底；**值一律 astype(str) 后剥 \`**——
  不要按 dtype==object 判断（StringDtype 不是 object，旧判断整列跳过剥反引号 →
  资金日期解析 NaT → 账期过滤后 0 行，2026-11-16 实证修复）。
- 必需列（清洗后）：订单号/资金日期(原\`结算时间)/实际结算金额/货款 + 16 项费用列。
- 账期过滤用「结算时间」→资金日期。商品数量转 int（基准 Excel 是数值列）。

## 2. 组件口径

- 销售货款 = 货款>=0；销售退款 = 货款<0（保留负号）
- 小额打款 = 售后补偿
- 平台费用 = **16 项费用列之和**：技术服务费/运营服务费/专享优惠/信息增值服务费/
  直播服务费/推广活动费/快递信息服务费/营销费用/佣金补偿/优惠活动金额/优惠券金额/
  满减金额/进口费用/运费/罚款金额/赔付金额
- 现金流 = 四者之和；**差异 = 实际结算金额 - 现金流**（自检列）

## 3. 硬门

明细「实际结算金额」合计 == 透视现金流合计（round 2），不等 → BillParseError
（原脚本 exit()）。**不平先查明细「差异」列非 0 行**——通常是上游新增费用列
没进 16 项公式。新费用列处理：diff 新旧列头 → 人类确认归属 →
加入 FEE_COMPONENTS（代码级+回归）。

## 4. 交付物与已知口径

`好衣库_好衣库_{店名}_{编码}_{账期}_账单整理.xlsx`：氚云导入模板 +
好衣库账单透视（固定 18 类中非零者）+ 好衣库账单整理（44 列全量明细）。

- 店铺编码注意：8 月原始目录标 HYK002，但影刀基准与店铺映射均为 **HYK001**
  （好衣库_秋水伊人）。跑之前先查 shops 确认编码，别照抄目录名。
- 原脚本 bug（多文件时资金日期取最后一个文件）插件已有意修正为按 df 自身列解析；
  单文件场景无差异。

## 5. 漂移应对速查

| 症状 | 先查 | 修法 |
|---|---|---|
| 账期过滤后 0 行 | 反引号剥离失效（dtype 判断回退）/ 结算时间格式变 | 保持无条件 astype(str) 剥 \` |
| 「缺少字段」 | 列名反引号格式变 / 费用列改名 | _RENAME 同步（代码级+回归） |
| 硬门不平 | 明细「差异」列非 0 行 → 新费用列 | 人类确认后扩 FEE_COMPONENTS |
| 商品数量合计对不上 | 文本 vs 数值 | 保持 to_numeric 转 int |

基准回归锚点：HYK001 2026-08（14642 行标准账单 / 明细 4386 行，硬门对平）。
