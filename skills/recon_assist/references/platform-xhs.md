# 小红书（xhs）账单整理 · 平台技能文档

> 适配器：`core/platforms/xhs.py`（承接 bill_arr.xhs_arr **结算单口径** ≈176 行）。
> 总体方法论见 bill-methodology.md。
> ⚠️ 原影刀脚本有两套对账来源：**结算单（主要，本插件已实现）** 与 订单/日账单
> （xhs_daily，≈120 行，**已弃用不再接**）。两者货款公式不同（日账单含政府券），
> 不要混用。bill_type=「小红书结算单」。用户给「订单」类报表时先核对是否拿错来源。

## 1. 数据源

- 单源 xlsx 结算单（文件名 `{店名}_RB…_{日期}_{uuid}.xlsx`），双 sheet：
  **订单结算** + **其他服务款**（「总览」sheet 忽略；缺 sheet 跳过不报错）。
- 订单结算必需列：结算时间/交易类型/动账金额/商品实付\/实退/平台优惠补贴/平台佣金/买手佣金/订单号。
- 其他服务款必需列：结算时间/业务款项/业务单号/动账金额/订单号。
- 账期过滤用「结算时间」。⚠️ 结算单文件名日期可能早于账期（XHS002 8月目录里是
  7月结算单，结算时间全在 7 月）——**账期内 0 行是合法状态**，见 §4。

## 2. 口径

**订单结算**：
- 货款 = 商品实付/实退 + 平台优惠补贴（**不含政府券**）
- 交易类型'结算入账'→货款收款；'退款'→货款退款（保留负号）
- 金额差异 = 动账金额 - 货款收款 - 货款退款 - 平台佣金 - 买手佣金（自检列，应≈0）
- 透视固定三类：货款 / 平台佣金 / 买手佣金（退款侧取 abs）

**其他服务款**：
- 业务类别 = 业务款项**原文**（上游新增款项会直接成为新类别，每月 diff 透视）
- 收款 = 动账金额>=0；退款 = <0（负数，透视时取 abs）
- 先账期过滤再透视（原脚本顺序）

## 3. 空账期导出（export_when_empty）

原 xhs_arr 账期内无数据**仍导出全零透视簿**（XHS002 8月基准实证：明细 0 行，
透视仍有货款/平台佣金/买手佣金三行全 0，氚云模板 0 行）。适配器声明
`export_when_empty=True`，pipeline 空行分支走导出而非 skipped。
**不要把这种批次当失败**；向用户汇报「该账期无结算数据，已按基准导出全零簿」。

## 4. 交付物

`小红书结算单_小红书_{店名}_{编码}_{账期}_账单整理.xlsx` 四 sheet：
氚云导入模板 / 小红书账单透视 / 小红书账单整理（订单结算 13 列）/ 小红书其他费用整理（10 列）。

## 5. 漂移应对速查

| 症状 | 先查 | 修法 |
|---|---|---|
| 「订单结算缺少字段」 | 「商品实付/实退」斜杠/列名变化 | 改必需列与公式（代码级+回归） |
| 金额差异列非 0 | 上游新增金额组件（如新补贴/新佣金列） | diff 列头，人类确认口径后加入公式 |
| 透视冒新类别 | 其他服务款新业务款项（原文即类别） | 引导人类定氚云科目，无需改码 |
| 货款口径跳变 | 平台优惠补贴/政府券口径变化 | 对照 xhs_daily 与结算单差异，人类确认 |
| 交易类型新值 | '结算入账'/'退款' 之外的值 → 货款收/退都 0 | 补 np.where 分支（代码级+回归） |
| 整店 skipped→全零簿 | 结算时间不在账期（正常） | 无需修；提示用户核对结算单导出区间 |

基准回归锚点：XHS003（5471 行）/ XHS005（207 行）逐 sheet 对平；
XHS002 空账期全零簿对平。
