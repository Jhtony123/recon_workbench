# 有赞（youzan）账单整理 · 平台技能文档

> 适配器：`core/platforms/youzan.py`（承接 bill_arr.yz_arr ≈150 行）。
> 总体方法论见 bill-methodology.md。

## 1. 数据源

- 单源 csv 对账单明细（文件名 `对账单-…-明细.csv`；同目录 zip 忽略）。
  zip 解压后 csv 在日期子目录里（`2026-08-01 00_00_00-…/`），文件收集已支持递归子目录。
- 读取：**utf-8**（不是 gb18030！与多数平台不同）；支付流水号/关联单号/下单时间/
  入账时间/业务单号 强制 str。
- ⚠️ **必须 index_col=False**：有赞 csv 列头 21 列、数据行 23 个字段（行尾多 2 个
  空字段），pandas 默认推断会把前两列当索引 → 整表错位（「类型」列变成订单号、
  金额全落错列、退款恒 0）。症状：货款 0 行 + 收款异常巨大 + 透视只有 1 类。
  2026-11-16 zip 解压实证修复；read_option 可覆盖 index_col。
- 字段值带 `\t` 尾巴（如 `提现\t`），_STRIP_COLS 各列 strip；字典里同时收了
  「提现」与「提现\t」两键兜底。
- 必需列：类型/名称/支付流水号/关联单号/业务单号/入账时间/收入(元)/支出(元)。
  ⚠️ 金额列名是**半角括号**「收入(元)」，上游改全角即缺列报错。
- 收款=收入(元)，退款=支出(元)（各自为正）；账期过滤用「入账时间」。

## 2. 分类：类型字典 + 充值二次分类

TYPE_DICT（12 条）：订单入账/退款→货款；交易手续费→**运费险**（原脚本口径，
不是手续费类！）；手机验证收费→账扣；消费者保障服务费-放心购/-退货包运费→
消费者保障服务费；余额支付/提现/提现手续费-快速到账/充值/佣金-分销员 各自成类。
未命中→「未匹配」。

**充值二次分类**（原 cz_adj）：类型=充值 且 名称含「缴纳保证金」→ 店铺保证金。

字典可被 biz_code 规则表整表覆盖（首次热修先全量导入 TYPE_DICT，方法论 §3）。

## 3. 交付物

`有赞_有赞_{店名}_{编码}_{账期}_账单整理.xlsx`：氚云导入模板 + 透视 +
有赞账单整理（9 列：类型/名称/实际业务类型/支付流水号/关联单号/业务单号/资金日期/收款/退款）。

无硬对平门；自检靠未匹配占比 + 透视合计 vs 原始收支合计。

## 4. 漂移应对速查

| 症状 | 先查 | 修法 |
|---|---|---|
| 读入乱码 | 编码从 utf-8 变 gb18030 | upsert_rule(read_option, encoding, gb18030) |
| 「缺少字段」 | 收入/支出括号全半角、列名变化 | read_option 或改 REQUIRED_COLUMNS |
| 未匹配增多 | 新「类型」值 | biz_code 热修（先全量导入）；注意 \t 尾巴变体 |
| 保证金归类错 | 名称话术变（「缴纳保证金」） | 改 contains 关键字（代码级+回归） |
| 提现类消失 | \t 尾巴格式变化 | strip 已兜底；仍异常则查字典键 |

基准回归锚点：YZ002（1260 行）/ YZ003（157 行）2026-08 逐 sheet 对平。
