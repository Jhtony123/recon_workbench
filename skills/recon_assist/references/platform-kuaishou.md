# 快手（kuaishou）账单整理 · 平台技能文档

> 适配器：`core/platforms/kuaishou.py`（承接 bill_arr.ks_arr ≈419 行）。
> 总体方法论见 bill-methodology.md。

## 1. 数据源：双源（资金账单 + 订单流水）

| 源 | 位置约定 | 读取参数 | 必需列 |
|---|---|---|---|
| **资金账单 csv** | file_paths 目录 `*.csv`（如 202608资金账单.csv） | gb18030；账务流水号/关联业务单号/入账时间/备注 str | 关联业务单号/入账时间/账务方向/发生额（元）/业务类型/描述 |
| **订单流水 xlsx** | 主目录下「订单」或「订单流水」子目录自动发现；或 `extra_files={"order":[路径]}` | read_excel；订单号/实际结算时间 str | 10 个组件列（§3），缺一即报错并列出可用列 |

- 缺订单流水直接 BillParseError（带 hint），不会静默只出资金账单。
  **AI 沟通认知（2026-11-16 用户口径）**：快手账单没有划分订单的费用类型，
  必须靠订单流水补全——用户没给订单时，明确提醒「快手需要 账单+订单 两个数据源，
  请补订单流水（可以是 zip）」，不要只跑资金账单凑数。两源均支持原始下载 zip。
- 关联业务单号带 `\t` 尾巴且大量 NaN（资金转账类无单号）——清洗用
  `.astype(str).str.strip().replace("nan","")`；**不要用 `.map(str.strip)`**
  （StringDtype 下 NaN 是 float，会 TypeError，2026-11-16 实证修复）。
- 收款=账务方向'收'的发生额，退款='支'的发生额（发生额本身为正）。
- 账期过滤用「入账时间」。

## 2. 资金账单分类

业务类型 type_dict：货款结算/结算后退款→交易货款，余额提现→提现；
再走描述关键字链 NOTE_RULES（12 条，顺序即口径）：退货补运费→运费险、
集运扣款→物流费、商责→订单赔付、退款-快手电商-→小额打款、快手小店退款→交易货款、
分账追回-超售后期-平台服务费→技术服务费、…cps推广者三方分佣户→推广佣金、
快手商品赔付-现金补偿→小额打款、发货异常用户体验赔付→订单赔付、小额打款、
违约金扣款/违约金罚单扣款→违约金。未命中→「未匹配」。
type_dict 可被 biz_code 规则表整表覆盖（方法论 §3 警告）；NOTE_RULES 改序必回归。

## 3. 硬门 + 货款改用订单流水展开（本平台核心口径）

**硬门**：资金账单「交易货款」净现金流 == 订单流水净现金流（round 2）：
`货款 - 货款退款 + 营销费用 - 技术服务费 - 预售技术服务费 - 达人佣金 - 团长佣金
 - 快赚客佣金 - 服务商佣金 - 其他收费`。
不等 → BillParseError（原脚本导出两 sheet 后 exit()）。先核对两源同账期、
订单流水多分段文件给全。

对平后：**账单剔除交易货款**，货款部分改用订单流水按组件列各自
pivot（线上订单号+实际结算时间）展开。ORDER_COMPONENTS（原始列→组件名→方向）：

| 原始列 | 组件名 | 方向 |
|---|---|---|
| 合计收入(元) | 货款 | 收款 |
| 订单退款(元) | **货款退款** | 退款（业务类别仍=货款） |
| 支付营销回退（元） | 营销费用 | 收款 |
| 技术服务费(元) | 技术服务费 | 退款 |
| 预售增收技术服务费（元） | 预售技术服务费 | 退款 |
| 达人佣金(元)/团长佣金(元)/快赚客佣金(元)/服务商佣金(元) | 同名 | 退款 |
| 其他收费 | 其他收费 | 退款 |

⚠️ 组件名「货款退款」是独立明细列名，业务类别映射回「货款」——两者不能混
（2026-11-16 实证：混用导致 KeyError）。括号全角/半角混用是上游原样，改列名先 diff。

## 4. 交付物

`快手_快手_{店名}_{编码}_{账期}_账单整理.xlsx`：氚云导入模板 + 快手账单透视 +
快手账单（5 列：线上订单号/资金发生日期/业务类别/收款/退款）。

## 5. 漂移应对速查

| 症状 | 先查 | 修法 |
|---|---|---|
| 「缺少订单流水文件」 | 「订单」子目录名变化 / 未给 extra_files.order | 补路径；目录改名则扩展 _order_files 子目录名 |
| 「订单流水缺少组件列」 | 上游改名/新增组件列（报错带 available_columns） | 同步 ORDER_COMPONENTS（代码级+回归）；新组件是否进净额公式需人类确认 |
| 硬门不平 | 两源账期不一致 / 分段文件缺 / 新组件列未进公式 | diff 差额；给全文件；确认公式 |
| 未匹配增多 | 新业务类型 / 新描述话术 | biz_code 热修（先全量导入 TYPE_DICT）；话术改 NOTE_RULES |
| TypeError strip | NaN 处理回退 | 保持 .str.strip() 写法 |

基准回归锚点：KS001 2026-08（64 行标准账单，硬门对平后逐 sheet 一致）。
