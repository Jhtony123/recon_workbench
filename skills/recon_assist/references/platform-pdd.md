# 拼多多（pdd）账单整理 · 平台技能文档

> 适配器：`core/platforms/pdd.py`（承接 bill_arr.pdd_arr ≈157 行）。
> 总体方法论见 bill-methodology.md。拼多多是**规则热修最友好**的平台：
> 新费用编码走 biz_code 规则表即可，多数情况无需改码。

## 1. 数据源

- file_paths 目录下 `*.csv`（商家后台「货款账单明细」导出，文件名
  `pdd-mall-bill-detail(mallid)_日期_序号.csv`；同目录的 .zip 是原始压缩包，忽略）。
- 读取：`encoding=gb18030, skiprows=4`（前 4 行是导出说明）。
- 必需列：商户订单号 / 发生时间 / 业务描述 / 收入金额（+元）/ 支出金额（-元）/ 备注。
  ⚠️ 金额列名含全角括号与正负号，上游改列名（如去掉「（+元）」）= 缺列报错。
- 尾部汇总行：定位含「**#支出合计**」的行，从该行起截断。
  上游改汇总标记文案 → 尾行混进数据（金额虚增）；行数异常时先查尾行。
- 备注全角括号统一转半角；账期过滤用「发生时间」。
- 多店注意：PDD004 等店一个月可能有多个 csv 分段（-2 后缀），目录给全即可。

## 2. 分类机制：业务编码字典（三层中最简单）

```
业务描述按 | 分割取首段 = 业务编码（如 0010002|交易收入-货款）
编码 → 字典映射业务类别；未命中 → 「未匹配」（显式暴露，不吞钱）
```

内置兜底字典 PDD_BIZ_CODE_FALLBACK（27 条）：
- 货款：0010002 / 0010005 / 0020002 / 0020005
- 技术服务费：0030001/2/3/5/11/15
- 小额打款：0040001 / 0130005；售后费用：0040002-7 / 0140002；账扣：0040008
- 消费者体验提升计划 0050002；多多进宝 0060001；跨店满返 0060002
- 店铺保证金 0070001；推广充值 0070003/4；提现 0080001；补贴 0090001；服务消费 0110001

**订单号口径**：备注里能正则匹配 `\d{6}-\d{15}`（如 260709-092411062561044）时
优先用备注单号（原 sepcial_type_adj，动态单号场景），否则用「商户订单号」。
上游改单号位数格式 → 正则失配 → 回落商户订单号（可能为空）→ SKU 匹配缺行。

## 3. 新费用类型处理（标准热修流程）

1. `query_bill_rows(batch_id)` 筛 业务类别=未匹配 → 汇总 业务编码+业务描述+金额；
2. 列表给人类定类（归既有类 / 新建类 / 挂账待定）；
3. **规则表热修**：`upsert_rule(platform=pdd, rule_kind=biz_code, rule_key=新编码, rule_value=类别)`。
   ⚠️ **整表覆盖语义**：规则表 biz_code 非空时整体替代内置字典！
   首次热修必须先把上面 27 条兜底字典全量 upsert 进规则表，再补新编码，
   否则老编码全部变「未匹配」（方法论 §3）。
4. 重跑该批次验证未匹配清零；规则文件可 diff、可追溯，无需改码无需重启。

长期稳定的新编码也可选择直接改 PDD_BIZ_CODE_FALLBACK（代码级），
效果等价，但要跑基准回归；规则表优先级更高，两处都改时以规则表为准。

## 4. 金额口径

- 收款 = 收入金额（+元）；退款 = -支出金额（-元）（支出列本身为负 → 退款为正）。
- 基准明细「退款」列保留符号原样（支出列若出现正值 → 负退款），
  统一五元口径取 abs——两条出口刻意保持各自原口径，不要"统一"。
- 无硬对平门；自检靠「未匹配」金额占比 + 透视合计 vs 原始收支合计（AI 主动比）。

## 5. 交付物

`拼多多_拼多多_{店名}_{编码}_{账期}_账单整理.xlsx` 三 sheet：
- 氚云导入模板（4 列）
- 拼多多账单透视（8 列）
- 拼多多账单（8 列：线上订单号/资金发生日期/账务类型/业务类别/收款/退款/备注/业务描述）

## 6. 漂移应对速查

| 症状 | 先查 | 修法 |
|---|---|---|
| 「缺少字段」 | 金额列名括号/符号变化、表头行数 | read_option 热修 skiprows/encoding；列名改 REQUIRED_COLUMNS |
| 读入乱码 | 编码从 gb18030 变 utf-8 | upsert_rule(read_option, encoding, utf-8-sig) |
| 金额虚增 | 「#支出合计」标记文案变，尾行混入 | 改 clean() 截断标记（代码级+回归） |
| 透视出现「未匹配」 | 新业务编码（最常见漂移） | §3 热修流程 |
| 货款行订单号为空 | 备注单号正则失配 + 商户订单号空 | 查备注原文，修 DYNAMIC_ORDER_RE |
| 分类正确但金额符号反 | 上游支出列改成正数 | 确认口径后修 _prepared/detail_frame 符号 |

基准回归锚点：PDD003 2026-08（107 行，透视 6 类逐分对平）；
PDD002/PDD004 为多 csv 分段店，改读取逻辑后建议一并重跑。
