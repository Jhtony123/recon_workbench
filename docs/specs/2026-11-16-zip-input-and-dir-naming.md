## 背景与问题

用户要求：① 直接给平台原始下载压缩包即可跑；② 输出目录按
`YYYY-MM-中文平台名-店铺名称-店铺编号` 命名，重跑覆盖不加数字后缀；
③ 特殊平台（唯品会/爱库存/小红书/快手/淘系/京东）口径明确化。

## 决策（用户确认）

1. **zip 全平台支持**：file_paths/extra_files 给 zip 或纯 zip 目录自动解压
   （runtime/extracted/ 按路径+mtime 缓存）；已有解压副本不碰 zip（防双份计账）；
2. **解析失败沟通认知**：找不到文件/列头不符时第一假设是**下载错了**
   （平台/账期/报表类型），把解压内容摆给用户确认，再考虑格式漂移；
3. **目录命名**：普通平台固定名重跑覆盖；爱库存 `YYYY-MM-爱库存`（一渠道多店
   AKC003/004 不写店铺）；唯品会两层 `YYYY-MM-唯品会-唯品中国` + 旬文件累积；
4. **唯品会多旬**：一个账单月三旬（上月下旬+本月上中旬），给父目录/整批 zip
   自动识别旬结构逐旬跑；底稿按旬子目录隔离；
5. **小红书**：结算单为主要口径（已实现），订单/日账单源弃用（认知记录）；
6. **快手**：缺订单流水明确提醒补「账单+订单」两源；
7. **淘系**：支付宝+微信必须一起跑（混合支付同订单号跨渠道）；
8. **京东**：钱包+结算单必需、E卡交叉校验；一天到账延迟 → 只给 period 自动推
   「上月末~月末」（8月→07-31~08-31）；显式 s/e 尊重用户。

## 实现要点

- base：collect_files 递归+zip；_extract_zip（gb18030 文件名兜底、非法字符净化、
  防 zip-slip）；expand_source_paths 供 ks 订单/淘系微信/jd 三源复用；
- artifacts：build_batch_dir 新命名+覆盖（vip 不清目录）；_DIR_RE_NEW/_DIR_RE_VIP
  解析兼容旧批次；BillBatch.drafts_subdir；
- pipeline：_vip_expand_xuns/_vip_run_xuns 多旬分发聚合；jd 日期窗口分支。
