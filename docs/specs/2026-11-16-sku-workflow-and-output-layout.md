## 背景：工程两个核心目标

1. **资金流水视角**（已完成）：平台原始资金账单 → 收支类型分类（收入/费用/往来/
   提现充值…），给财务做账务处理的分类依据。
2. **货物视角**（待启用）：从整理结果分离**货款**的收款/退款，按**订单号**查
   专门准备的巨益 OMS 库找货物记录，生成 SKU 匹配对账结果，支撑
   主营业务成本 / 发出商品 / 不做处理 的判断。

## 流水线（分步执行，前三步各有独立产物）

```
开始 → 账单整理 → SKU对账 → 成本匹配 → 数据库回传标记 → 氚云回传 → 结束
         ↓产物       ↓产物      ↓产物        ↓状态迁移         ↓状态迁移
```

- SKU对账先跑**不带成本**的版本，产出一批 Excel；
- 财务在 ERP 单独跑成本核算生成成本表 → 成本匹配 = SKU结果 + 成本表 → 新交付物；
- 数据库回传：写巨益 OMS 生产库打对账标记（全流程唯一写生产动作，须显式确认门）；
- 氚云回传：现阶段导出导入模板 + 手工导入。

## 状态机纪律（用户原话口径，2026-11-16 确认）

- **成功迁移、失败留守**：成本匹配成功的文件从 未匹配成本/ **移动**到 已匹配成本/；
  个别平台脚本失败的批次**留在原目录不删**——目录本身就是失败检查看板；
- 回传同理：成功的移动到 已回传数据库/，失败的保留在 已匹配成本/；
- 流程全部走完时：未匹配成本/ 与 已匹配成本/ 为空，只剩 已回传数据库/ 有数据；
- **不做「每次执行清空重来」**（首轮理解有误，已纠正）。

## 粒度与合并
