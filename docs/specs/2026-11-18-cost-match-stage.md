## 背景

财务每月在金蝶 ERP 完成成本核算后提供物料成本表（`物料成本_YYYYMM.xlsx`）。
本阶段把表中**不含税实际成本单价（SPU/款号颗粒度）**回填到 SKU 匹配表
（采购单价/发货成本），重算透视毛利（收入/1.13 − 发货成本），产出「成本匹配」版结果，
并把批次从 `sku匹配/未匹配成本/` 迁移到 `sku匹配/已匹配成本/`。

上游 SKU 对账（2026-11-17 spec）已启用：10 月 38 店产物在位、三项金额校验 38/38 OK。
影刀 10 月成本匹配基准（`桌面\2026.10月账单\SKU匹配汇总-已有结果可作为对照验证\成本匹配\`，
全平台 52 份）可作回归对照。

## 业务口径摘要（细节以 methodology 为准）

### C1 成本表读取（core/cost.py load_cost_base，已有基础）
- 按账期推 sheet（`cost_sheet_for_period`，10月→10月末）；禁止默认读第一个 sheet。
- 键=`规格型号`（str），去重后 dict；单价保留**原始精度**（unit_cost_raw，Decimal），
  空单价 fillna(0)。⚠️ `物料编码` 列是品牌值不是键；整行全空的残留行剔除。
- 异形表转换层：输入不符合固定约定时，先归一为 物料编码/物料名称/规格型号/数量/单价
  五列 + `{月}月末` sheet 的标准文件（转换脚本独立，转换结果落批次底稿留痕）。

### C2 明细回填（收/退款对称，methodology §2）
0. **输入=SKU 对账底稿 match_detail.csv（分域、内部全列）**，不读交付 Excel——
   影刀读 Excel（元域）是其文件态使然；插件底稿信息更全（含数据来源/店铺编码等内部列），
   换算后与 Excel 等价（已验证两阶段明细除回填列外逐格一致）。
1. 数量取 abs；**明细侧数量/货款分摊/结算金额保持原符号（正数）**，取负只发生在透视
   （基准实测：HYK/VIP 成本阶段退款明细数量全为正，与 SKU 阶段一致）；
2. 采购单价=款号查表 fillna(0)（**本阶段无 NaN 语义**；现有 apply_cost 的
   keep_zero/NaN 分支是 match 阶段语义，须加 stage 参数或独立 cost 分支，不得复用）；
3. 发货成本=round(|数量|×原始精度单价, 2)（元域 Decimal 乘完再 round，禁先量化到分；
   HALF_UP 与 pandas half-even 在 10 月全量数据实测 0 分歧行，维持 HALF_UP 并登记）；
4. 占位符重写：款号 None/空→无款号、吊牌价 None→无吊牌价、商品名称/年份/季节/品牌照基准；
   **id 列空值→字面串 "None"**（影刀 astype(str) 副作用，基准 47 行实测；为对齐基准照复刻）；
5. **FR 行级特例**：店铺名称含「唯品会」& 品牌==FR → 发货成本=标准成本
   （改造点：dormant 的整店 force_std_as_ship 改行级；VIP 非 FR 正常查表，AKC 无特例）；
6. **标准成本/标准成本单价一律透传，禁止重算**（审核新增，关键）：
   现有 apply_cost 会重算 标准成本=单价×数量——这会**覆盖 VIP FR 的结算金额特例**
   （基准实测 FR 62044 行 标准成本=结算金额、0 行=单价×数量）。cost 阶段只透传
   SKU 阶段已写入的标准成本（含 FR 覆盖值），两条成本线分离；
7. 特殊情况说明列（第 32 列）：款号=无款号→「无款号」；款号有值但表无此款→
   「成本表无此款」；其余留空。FR 行发货成本=标准成本属正常特例，**不标注**。
8. **采购单价展示列=原始精度**（审核新增，关键）：基准该列存全精度小数
   （如 52.212389380531，HYK 实测与成本表值 1e-6 内相等），**不是**量化到分的值。
   现有 apply_cost 把展示列存 unit_cost_fen（分）→ cost 阶段出口必须改用
   unit_cost_raw 原样写出（内部计算仍可存分，出口层单独带 raw 列），
   否则与基准逐行差小数尾。发货成本仍是 round 后的 2 位小数。

### C3 透视重算（core/pivots.py stage="cost"，_add_margin 已实现双口径）
- **必须从占位符重写后的明细重新透视**，不得复用 match 阶段透视产物（审核新增）：
  款号/吊牌价是透视分组键，None→无款号/无吊牌价 重写会改变分组
  （基准实测：HYK 款号透视两阶段同为 207 行但键集合不同）；
- 匹配透视 14 列（无店铺编码）：退款侧五 value 取负（**仅透视取负，明细保持正数**）；
- 店铺 13 列 / 款号 18 列（均无店铺编码）：毛利=round(收入/1.13−发货成本,2)、
  率=round(毛利/(收入/1.13),4)，收入 0→率 0；bp 存率、出口还原；
- 冲发出商品数量=真数量（cost_match 无 look_sku 笔误）；
- 删行规则照 methodology §3.2；聚合口径（先全额聚合、成本按意见过滤回填）不变。

### C4 输出与状态机
- 每店一份 6-sheet Excel：店铺透视(13)/款号透视(18)/匹配透视(14)/收款匹配(**32**=31+特殊情况说明)/
  退款匹配(32)/已匹配的巨益单号(3，原样透传)；
- 底稿：cost_detail/pivot_* csv（分）+ manifest（含 cost_file、sheet、缺失款号清单、税率）；
- **成功 move、失败留守**：整批目录 未匹配成本→已匹配成本（artifacts 状态机既有预留）；
  迁移前校验导出文件完整（6 sheet 都在）；重跑幂等（已匹配成本目录存在同名批次→覆盖并留痕）。
- **特例批次粒度**（审核新增）：
  · 唯品会：一个账期多旬共用一个批次目录（目录内多份旬文件）——**全部旬都成本匹配成功
    才迁移整目录**；单旬失败则该目录留守，汇报标明失败旬；
  · 爱库存：一个渠道一个批次（多店一簿），迁移粒度=渠道批次；
  · 批量执行时单店失败不阻塞其余店铺；迁移用 shutil.move（同盘原子 rename），
    失败时不留半截目录（先导出到临时名、校验后 move）。
- **已匹配成本目录里的批次可重跑**：run_cost 的批次发现范围含 已匹配成本/
  （财务月中更新成本表后重算场景），重跑成功原地覆盖、不再迁移。

### C5 入口接线（吸取 match 阶段 Q8 遗留教训，本期一并做）
- run.py / actions.start_recon 按 stage 分发：bill→run_bill、match→run_match、cost→run_cost
  （顺手补上 match 的遗留接线）；
- run_cost 参数：period、cost_file（缺省在 结果根/{YYYY-MM}/ 找 物料成本_YYYYMM.xlsx）、
  bill_batch_id/批次选择（缺省=该账期 未匹配成本/ 全部批次）、include_tax（默认否）；
- cost_match() MCP 工具接 run_cost；capability_status/config.json/UI 状态同步
  （cost 改 active，match 状态表述修正）；
- job_log 留痕：success/partial（有成本缺失行）/failed（成本表缺失/sheet 不存在/对平门不过）。

## 验收

- HYK：6 sheet 与基准一致（除 明细第 32 列「特殊情况说明」为用户批准附加列；
  采购单价**原始精度**=表值（1e-6 内）、发货成本=round(|数量|×原始单价,2) 逐行对平；
  毛利锚点 44510/1.13−17889.54=21499.84；id 空值行=字面串 "None"（47 行）；
  款号透视键集合按重写后占位符对齐，非按 match 阶段键）；
- VIP 上旬：FR 62044 行 发货成本=标准成本 **且 标准成本=结算金额保持不被重算覆盖**、
  非 FR 查表；AKC 3727 行全查表；
- 缺失款号行（DY009 9 行）：采购单价/发货成本=0 + 特殊情况说明=成本表无此款 + 汇报清单；
- 守恒校验（新增）：成本阶段明细的 货款金额/货款分摊金额/结算金额/数量/标准成本
  与 match 阶段产物**逐列合计相等**（成本回填不得改动这些列；HYK/VIP 基准已验证）；
  「已匹配的巨益单号」与 match 阶段**逐格一致**（原样透传）；
- 白名单预期差异：OMS 数据时点漂移（同 SKU 阶段归因）、L147 笔误修正行、第 32 列附加；
- 批次迁移：成功后 未匹配成本/ 无残留、已匹配成本/ 完整；失败注入测试留守；
  VIP 单旬失败整目录留守；已匹配成本目录重跑原地覆盖；
- 全程不写生产库；validate_extension + UI 探活零报错。
